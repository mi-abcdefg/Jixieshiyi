# 开发日志：电控与嵌入式软件

## 1. 电控系统目标与组成

电控开发的目标是实现 PS2
手柄输入、四轮麦克纳姆底盘运动、四舵机机械臂控制以及整车任务调度。当前控制器以
STM32F103 核心板为基础，底盘使用两个 DRV8833 驱动模块，机械臂使用三个
SG90 和一个 MG995 舵机，PS2
接收器作为无线输入端，另通过无线继电器实现底盘供电切断。

软件采用 C/C++ 工程组织，底层外设由 STM32 定时器/GPIO
等资源实现，任务调度采用 FreeRTOS（CMSIS-RTOS
v1）。文中时间线和测试结论来自当前开发记录；未记录的测试结果不推定为通过。

## 2. PS2 遥控通信

### 功能描述

`RemoteCommTask` 每约 `10 ms` 与 PS2
接收器通信一次，读取应答数据并解析按键、模式及左右摇杆模拟量，供底盘和机械臂任务使用。PS2
通信采用 GPIO 位操作时序。

### 开发历程

#### 2026/09/13：驱动和解码文件起步

创建 PS2
驱动文件与解码文件。此时驱动文件已有初步结构，解码仍在编辑，代码尚未完成实机验证。

#### 2026/09/14：搭建通信任务

初步完成 PS2 通信链路，建立 `RemoteCommTask`
周期任务，并把读取到的指令存储起来，供底盘及其他控制任务读取。

#### 2026/09/17：引脚与初始化调整

根据实际接线修改引脚配置，完善初始化流程。

#### 2026/10/02：模拟模式与摇杆有效性

调试中发现手柄按键能够响应，但摇杆没有有效模拟量。原因是仅发送 `0x42`
轮询命令并不能保证手柄进入模拟模式，摇杆数据可能固定为 `0x00` 或
`0xFF`。

处理措施：

1.  新增 `PS2_ConfigAnalogMode()`，上电后尝试将手柄切换到模拟模式。
2.  增加摇杆数据有效性检查；四个摇杆字节全部为 `0x00` 或全部为 `0xFF`
    时按中位处理，避免无效数据被解释为满速指令。
3.  增加按键值与模式字节读取接口。
4.  移除工程中闲置的 SPI1 配置，避免其与 PS2 使用的 PB3/PB4/PB5
    产生复用冲突。
5.  将 PC13 指示灯用于显示 PS2
    链路状态：未连接时快闪，连接后依据手柄模式显示状态。

开发记录注明手柄已完成配对锁定。后续仍应在整车供电、不同启动顺序和连续运行条件下复测通信稳定性。

## 3. 底盘运动控制

### 功能描述

底盘控制由麦轮运动学解算和电机 PWM 驱动组成。`ChasisControlTask` 每约
`10 ms` 读取左右摇杆指令，将期望平移和旋转转换成四轮目标线速度，再映射为
PWM 占空比输出。支持 L1 快慢速模式切换，L2 电机使能通断；后续增加 R2
操作对象切换。

### 开发历程

#### 2026/09/13：建立麦轮解算和电机驱动

创建底盘麦轮解算文件和电机驱动文件，形成初步的四轮运动控制逻辑。此阶段代码尚未实测。

#### 2026/09/14：完成初步控制链路

初步完成底盘运动控制逻辑。控制任务周期读取 PS2
摇杆，并生成四轮运动指令，可表达任意方向平移和原地旋转。

#### 2026/09/17：完善初始化

继续调整外设和控制模块初始化流程，为后续实机调试做准备。

#### 2026/10/02：底盘首次真正运动及量纲修复

补齐从摇杆输入到电机 PWM 的完整量纲链路。早期代码将范围约为 `±2.0`
的浮点轮速直接截断为整数，造成占空比极小，电机无法有效运动。修改后将目标速度正确换算为
PWM 占空比。

同时完成以下修正：

-   实测轴距、轮距均为 `12 cm`，将测量值写入麦轮解算参数。
-   修正归一化符号错误，改为按绝对值最大的轮速等比例缩放，避免倒车时饱和判断失效。
-   原地旋转上限不再固定为 `2.0 rad/s`。依据
    `k = 0.5 × (轴距 + 轮距) = 0.12 m`，并结合最大轮速计算旋转上限，使旋转输入能够合理利用驱动能力。
-   增加 DRV8833 使能控制：上电默认不使能，由 L2 键切换通断。
-   增加电机正负极接反的软件修正开关。
-   增加 L1 慢速模式，推到底时目标速度为满速模式的约
    50%，并支持按键切换。
-   将 TIM2/TIM3 的 PWM 频率由约 `15 Hz` 提高到
    `20 kHz`；占空比换算依据运行时 ARR
    计算，减少频率变更带来的代码耦合。

#### 2026/10/10：底盘运动代码测试与修复

对底盘运动模块进行测试，并根据测试情况优化和修复运动逻辑。现有记录未给出完整测试矩阵和量化误差，因此这里只记录完成了模块测试与修复，不将所有运动方向视为已经通过最终验收。

#### 2026/10/17：适配 B 车底盘及操作模式门控

根据 B 车实际轮组安装方向，将后两轮电机方向取反；新增
`CHASIS_OMEGA_INVERT`
方向翻转配置，修正右摇杆旋转方向与操作者预期相反的问题。

新增 R2
操作对象切换：底盘模式和机械臂模式之间切换，上电默认底盘模式；进入机械臂模式后底盘轮速指令清零，降低操纵机械臂时底盘误动作的风险。

## 5. FreeRTOS 任务框架

### 功能描述

当前工程基于 FreeRTOS（CMSIS-RTOS v1），主要任务包括：

-   `RemoteCommTask`：PS2 通信；
-   `ChasisControlTask`：底盘控制；
-   `ArmTask`：机械臂控制；
-   状态指示灯任务；
-   舵机通道辨识测试任务（平时不启动）。

各任务通过 `TaskBase` 基类统一封装创建过程。

### 开发历程

#### 2026/10/02：定位任务创建失败与堆不足

当时出现手柄正常、指示灯正常但电机不动的情况。排查发现 CubeMX
重新生成代码时会把 `configTOTAL_HEAP_SIZE` 覆盖回默认
`3072`，而多个任务的栈空间合计约 `5 KB`，导致 `ChasisControlTask`
创建失败。

由于任务创建失败只返回错误码，表面上并不一定出现明显异常，问题较难定位。处理措施：

1.  将系统堆调整为 `10240` 字节，并放在 USER CODE 区域，降低被 CubeMX
    覆盖的风险。
2.  增加堆分配失败钩子，堆不足时让 PC13 快闪报警。
3.  清理 `main.c` 中位于 `osKernelStart()` 前的调试
    `while(1)`，避免调度器无法启动。
4.  修复 `osThreadDef_t` 未初始化引发的潜在野指针问题。
5.  将 `TaskBase::start()`
    修改为返回任务创建结果，便于上层发现创建失败，而不是默默继续运行。

#### 2026/10/17：整合机械臂任务

新增约 `20 ms` 周期的
`ArmTask`、舵机通道辨识测试任务和独立的底盘/机械臂操作模式模块。当前设计为底盘任务写入模式状态，其余任务只读。记录中说明任务数增至五个，并已核算任务栈与
`10 KB` 堆的余量；后续若增加功能，仍需重新进行内存核算。

## 6. 机械臂电控与运动算法

### 功能描述

机械臂控制采用分层结构：舵机驱动、关节空间控制、逆运动学/动作序列/摇杆点动、任务编排。四路舵机
PWM 由 TIM4 输出，使用 PB6--PB9。由于底盘已使用相关 TIM3
资源，合并工程时将舵机定时器调整为 TIM4。

### 开发历程

#### 2026/10/17：合并独立机械臂工程

将独立工程 `CRTC_RobotArm`
的动作序列状态机、舵机驱动和按键事件层合并至整车工程。动作序列状态机保持
C 语言编译方式。合并前在 `feature/arm-merge`
分支保存底盘基线，以便出现回归问题时回退。

同时新增柱坐标逆运动学模块和摇杆点动模块；此前独立机械臂工程主要具备固定动作序列。

#### 逆运动学角度约定统一

测试发现肘上解计算出的肘关节相对角为负值，而原限幅范围为
`0°–180°`，导致角度被夹到
`0°`，松开摇杆再操作时舵机会跳到极限位重新起步。

将肘关节角度域统一为 `-180°–0°`，初始角设为
`-90°`（电气中位），并对齐逆解、舵机限幅和动作表中的角度定义。开发记录指出，上电位形经过正解---逆解往返检查后保持自洽。

#### 关节速度限幅

末端采用恒定笛卡尔线速度点动时，靠近全伸或全折边界会出现逆解放大，造成关节角速度尖峰。为此每个控制周期对三个关节角度增量统一限幅，当前记录值为
`80°/s`；超限时按比例同步减速，以尽量保持末端路径形状并平滑停靠。

#### 舵机方向与通道辨识

根据实物安装方向对肩、肘舵机方向进行软件翻转；四台舵机上电初始角统一为
`90°`，肘关节按其角度约定使用 `-90°`。脉宽限幅按舵机手册调整至
`500–2500 μs`。

2026/10/17 的通道辨识结果为：PB6=夹爪、PB7=肩、PB8=肘、PB9=底座
MG995。该结果与最初接线描述中 PB6/PB9
的功能顺序相反，因此已按实测结果修正软件配置。四套预置动作角度在记录中仍为占位值，需完成实物标定后才能视为正式动作。

#### 操作方式

-   R2：切换底盘/机械臂控制对象。
-   机械臂模式下，左摇杆控制末端在水平面移动；右摇杆 X
    控制底座旋转，右摇杆 Y 控制上下点动。
-   △、○、×、□：触发预置抓取/放置动作序列。
-   SELECT：取消动作。
-   手动推杆：自动打断正在执行的动作序列。

预置动作使用 smoothstep
插值限制动作变化；最终角度与抓取效果仍需通过实物标定和连续测试确认。

## 8. 调试经验总结

-   **先核对完整量纲链路**：摇杆值、轮速、归一化比例、PWM
    计数值之间必须有明确换算，不能直接截断浮点数。
-   **代码配置不等于硬件连接**：引脚定义必须与原理图、PCB
    网络和焊接实物相互核对。
-   **把任务创建结果显式化**：RTOS
    任务创建失败应立即暴露，不能依赖"看起来没有报错"。
-   **统一角度定义**：逆运动学、舵机机械安装、限幅范围和动作表必须使用同一套角度约定。
-   **在边界处考虑速度**：末端速度恒定不意味着关节速度恒定，应对关节增量或速度进行约束。
-   **先分模块验证，再做整机集成**：PS2、单电机、单舵机、动作序列和操作模式分别验证后再合并，有助于缩小故障范围。
