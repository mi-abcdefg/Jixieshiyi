# 机械臂动作模块·重建规格

> `feature/arm-jog-only` 分支的机械臂当前是**纯摇杆点动基线**。本文件是动作模块的重建规格：
> 要达成什么效果、怎么构建、以及必需的数据。按本文件实现即可，无需翻阅旧代码；
> 如需参考，旧实现完整保留在 main 分支（例：`git show main:Arm/Src/arm_action.c`）。
> 最后更新：2026/10/20

## 1. 目标效果（实现完成的验收标准）

| 编号 | 效果 | 验收方法 |
|---|---|---|
| E1 | ○ 键：夹爪在"开 / 合"两档间切换，两档角度实车标定 | 任一位置按 ○，两档往返稳定 |
| E2 | △ 键：回收缩——从任意位形经过渡点收到收缩位 (0,165,0)，夹爪闭合（原为十字键↑，2026/10/21 改到 △） | 任意姿态按 △，臂按路径收拢不扫到周围 |
| E3 | × 键：篮内外转移——篮外→篮内经两个过渡点到篮内点；篮内→篮外反向到出篮终点（到位后夹爪闭合）；走向按起始位形自动判定 | 从工作位按 ×，**底座必须摆向篮子侧并停在篮内点**（此条同时是"新固件已生效"的判据） |
| E4 | L2 键：卸力（可徒手摆位）⇄ 恢复；恢复时**逐路给力**——先只让大臂（肩）有力并撑直到 90°（底座/肘/夹爪仍是软的），再让大臂保持、底座单独回中位，收尾才把肘（小臂）与夹爪一起给力（不再先整臂弹回卸力前姿态） | 卸力恢复后臂自动走出当前位置（先撑大臂、再转底座） |
| E5 | 通用：动作运行中推杆 / SELECT / 再次动作键可打断，臂停在当前位置 | 动作中推杆立即停 |
| E6 | 运动品质：各关节恒角速度、到位停留约 0.3s、指定帧切换夹爪、动作完成后回到空闲可立即触发下一个 | 连续触发不卡死 |
| E7 | 十字键长按：机械臂末端持续上下平移（↑↓）/ 水平前后平移（←→），走柱坐标逆解 | 长按 ↑ 末端上升、← 末端伸出，中途松手即停，贴到行程边界不甩臂 |
| E8 | R1 键：机械臂模式下切换"正常 ⇄ 动作选择菜单"；菜单内 8 个键（左十字键 + 右面键）各对应一个动作槽位（当前占位） | 按 R1 进菜单后摇杆/夹爪不响应，再按 R1 恢复；R2 仍是底盘⇄机械臂 |

## 2. 参考构建思路

### 2.1 模块划分（全部 C++，推荐命名）

| 模块 | 文件 | 职责 | 关键接口 |
|---|---|---|---|
| 关键帧层 | `Arm/Inc/arm_keyframe.h` `Arm/Src/arm_keyframe.cpp` | 纯数据：用户角→命令角换算 + 命名关键帧表。**改角度只改这里** | `ArmKeyframe get_keyframe(KeyframeId id)` |
| 动作引擎 | `Arm/Inc/arm_action.h` `Arm/Src/arm_action.cpp` | 状态机：按路径表逐帧逼近关键帧、切夹爪、推进/取消。**不认识按键和 PS2** | `start(ActionId, now_ms)` `update(now_ms)` `cancel()` `get_state()` |
| 按键输入 | `Arm/Inc/arm_button.h` `Arm/Src/arm_button.cpp` | PS2 位图 → 边沿事件 → 按键决策（E1~E5、E8 的绑定都在这里），另含十字键末端点动的按键解释 | `feed(buttons, connected)` `take_events()` `apply(now_ms)` |
| 末端点动 | `Arm/Inc/arm_endpoint.h` `Arm/Src/arm_endpoint.cpp` | 柱坐标末端点动（E7）：正解→增量→逆解→关节增量限速。复用 `arm_ik` | `arm_endpoint_jog(now_ms, dz, dr)` |

编排（已有，不需新建）：`arm_task.cpp` 每周期喂按键 → 调 `apply()` → 调 `arm_action_update()`；摇杆点动照旧走 `arm_manual`。

命名沿用工程现有 snake_case；新文件全部 `.cpp`，接口直接用 C++（全链路无 C 编译单元，**不需要 extern "C"**）。旧版的 gamepad/robot_control 两层合并为 `arm_button` 一个模块。

### 2.2 引擎设计要点

1. **数据与逻辑分离**：引擎只认 `KeyframeId` 序列；角度全部来自关键帧表。
2. **路径**：每个动作 = 一个 `KeyframeId` 数组。转移类动作准备两条路径（篮内/篮外），启动那一刻按当前位形二选一，之后不再切换；两条长度可以不等（引擎按选中那条的帧数推进）。
3. **推进**：以 20ms 固定节拍步进（与 `ArmTask` 周期严格一致）。每帧先把用户角换算为命令角目标（哨兵 KEEP = 保持该关节当前值），三关节以恒角速度逼近（底座 90°/s、肩 60°/s、肘 60°/s，与点动快速档同源 `arm_manual.h`）；全部到位后按该帧定义切换夹爪，停留 ~300ms 进下一帧。
4. **状态机**：`IDLE → RUNNING → IDLE`。取消 = 保持当前位置立即回 IDLE；**正常完成也直接回 IDLE**（不留中间态）。
5. **打断**：运行中任一摇杆轴越过**打断阈值**即取消。打断阈值必须显著大于点动死区（建议 0.15 vs 0.02），否则摇杆静置漂移会在第一帧误杀动作。
6. **关节写入**：一律经 `arm_control` 的 `arm_get_pose()/arm_set_pose_masked()`（读回=命令角，非反馈）；夹爪经 `gripper_set/gripper_toggle/gripper_jog`。
7. **逐帧给力**：关键帧带 `power` 掩码（默认整臂），只有本帧通电的关节会被写、被推进——卸力恢复的"脱离"动作靠它实现"大臂（肩）先有力、其余关节仍是软的"。动作结束时（完成/取消）由引擎统一补回全有力。

### 2.3 工程要求

- 新源文件登记进 `CMakeLists.txt` 的 `add_executable`；`Arm/Inc` 已在 include 路径，无需改。
- 构建命令：`ninja.exe -C cmake-build-debug-stm32`（全工程唯一烧录产物 `CRTC2026_RobotA.elf` 在该目录）。
- 分层铁律：`Arm/` 不 include PS2 与 Task；PS2 读取接口只有 RemoteCommTask 能调；`ControlMode` 只有底盘任务写。
- 链接带 `--gc-sections`：不可达代码会被整段裁掉；确认新模块已链接查 `.map`，不在 `Discarded input sections` 里即生效。

## 3. 必需数据（实现时照抄，实车标定后更新数值）

### 3.1 舵机通道与角度域（`servo_driver.cpp` 配置表，勿改数字）

| 关节 | 通道/引脚 | 舵机 | 命令角域 | 上电初始 | reversed |
|---|---|---|---|---|---|
| 夹爪 SERVO_GRIPPER | TIM4_CH4 / PB9 | SG90 | [0°, 180°] | 90° | false |
| 肩 SERVO_LINK_1 | TIM4_CH2 / PB7 | SG90（11cm 连杆） | [15°, 165°] | 90° | true |
| 肘 SERVO_LINK_2 | TIM4_CH3 / PB8 | SG90（8.5cm 连杆） | [−120°, +60°] | −30° | true |
| 底座 SERVO_BASE_Z | TIM4_CH1 / PB6 | MG995（绕 Z） | [90°, 270°] | 180° | false |

脉宽恒为 500~2500µs；脉宽 = 500 + ratio×2000，ratio = (命令角−min)/(max−min)，reversed 时取反。所有写入双重限幅，越界脉宽不会出现。底座命令角 180° = 臂朝车头方向。

> **实装说明（2026/10/21）**：重建时发现 `servo_driver.cpp` 的配置表"通道换对了、角度域没跟着走"——下标 0（夹爪）拿着底座的
> `[90°,270°]/180°`，下标 3（底座）拿着夹爪的 `[0°,180°]/90°`，导致"↑ 和 × 落点相同、且都不是关键帧位形"（底座 user 90 与
> 180 被夹成同一脉宽）与"○ 只能观察到开"（夹爪只跑得动很小一段）。已把角度域/初始角按 `ServoId_t` 归位，**数值与上表完全一致**，
> 未做任何重新标定。同一次修正里把通道标注改成上表这一版：判据是通道辨识的观测"命令底座时动的是夹爪"，即底座在 PB6、夹爪在 PB9。

### 3.2 用户角换算（关键帧存储用 0~180 用户角，与安装方向解耦）

```cpp
constexpr float kKeep = 255.0f;              // 关键帧字段哨兵：保持当前值
constexpr float base_user_to_cmd(float u)     { return 270.0f - u; }  // user 0=工作侧端(cmd 270)，180=篮子侧端(cmd 90)
constexpr float link1_user_to_cmd(float u)    { return u; }           // 肩：2026/10/21 镜像后 user 0=下推极限，180=上推极限
constexpr float link2_user_to_cmd(float u)    { return u - 120.0f; }  // 肘：user 0=下推极限(cmd −120)，180=上推极限(+60)
constexpr float base_cmd_to_user(float c)     { return 270.0f - c; }  // 位形判定用读回（须与正变换互为逆）
constexpr float link1_cmd_to_user(float c)    { return c; }           // 与上式互逆
```

**标定项（2026/10/21 已执行一次）**：底座 user 0/180 与物理两端的对应关系须在整车复核——×键验收（E3）同时完成此项。
实测反馈"user 0 落在预想的 180 位置"，即原式 `cmd = 90 + u` 与实物相反，**已翻转为 `cmd = 270 − u`**（即上表这一版）。
以后再遇到镜像，同样只翻 `base_user_to_cmd / base_cmd_to_user` 两行，**不要改关键帧数值**。

### 3.3 底座换算自检样例

| 用户角 | 命令角 | 脉宽 | 物理位置 |
|---|---|---|---|
| 0 | 270° | 2500µs（上限） | 工作侧端 |
| 90 | 180° | 1500µs | 初始方位（臂朝车头） |
| 180 | 90° | 500µs（下限） | 篮子侧端 |

### 3.4 关键帧初始值（底座, 肩, 肘 = 用户角；夹爪 = 开/合/不变；power = 本帧通电关节）

| KeyframeId | 底座 | 肩 | 肘 | 夹爪 | power | 用途 |
|---|---|---|---|---|---|---|
| `kBasketHigh` 篮上高点 | 180 | 90 | 90 | — | 全臂 | 篮子上方过渡位 |
| `kOuterHigh` 外侧高点 | 90 | 100 | 80 | — | 全臂 | 初始位附近过渡位 |
| `kRetract` 收缩位 | 0 | 165 | 0 | 合 | 全臂 | 回收缩终点 |
| `kBasketIn` 篮内点 | 175 | 70 | 25 | 开 | 全臂 | 转移·篮侧端点 |
| `kPickupLow` 出篮终点 | 90 | 75 | 40 | **合** | 全臂 | 转移·外侧端点（2026/10/21 起终点夹爪为闭合态） |
| `kEscapeShoulder` 脱离1 | KEEP | 90 | KEEP | — | **仅大臂** | 只撑直大臂（肩），底座/肘/夹爪仍卸力 |
| `kEscapeYaw` 脱离2 | 90 | KEEP | KEEP | — | **大臂+底座** | 大臂保持 90，底座回中位 |

篮内判定（转移动作选路用）：`底座用户角 ≥ 160 且 肩用户角 ≤ 100` → 判为篮内。阈值以**用户角**表达，约定不变（篮子侧 = 用户角大的一端），因此 3.2 的方向翻转**不影响**这两个阈值，无需跟着改。

### 3.5 动作路径与按键绑定

```cpp
retract   : 篮内 { kBasketHigh, kRetract } / 篮外 { kOuterHigh, kRetract }        // △
transit   : 篮内 { kBasketHigh, kOuterHigh, kPickupLow }                          // ×（终点夹爪合）
            篮外 { kOuterHigh, kBasketHigh, kBasketIn }
escape    : { kEscapeShoulder, kEscapeYaw }                                       // L2 恢复后自动
```

○ = 夹爪两档切换（档位角起 60/120 命令角，实车标定后更新）；L1 = 点动快/慢两档（`arm_manual` 机制已在，绑回即可）。动作运行中：推杆/SELECT/动作键打断（E5）。十字键在机械臂模式下用于末端点动（见 3.6），不再绑定回收缩。

**夹爪只在"到位"时切**：关键帧的夹爪状态在三关节到位之后才下发，所以"出篮终点夹爪合"是**到达终点才合爪**——路径途中不动夹爪。反过来说，**不要**在出篮路径开头插一个"先合爪"的帧：那会在篮子里把方块夹住、再一路带出来。

### 3.6 末端柱坐标点动与动作菜单（E7 / E8）

**末端点动**（`arm_endpoint`，机械臂模式 + 正常 UI + 未卸力时有效）：

| 参数 | 值 | 说明 |
|---|---|---|
| `ARM_ENDPOINT_Z_MPS` / `ARM_ENDPOINT_R_MPS` | 0.04 / 0.04 | 末端上下 / 前后平移速度 [m/s]，臂展约 19.5cm |
| `ARM_ENDPOINT_SHOULDER_OFFSET_DEG` | 90 | 几何仰角 = 肩命令角 − 90（依据"肩 user 0 = 竖直 = 命令角 180"） |
| 关节增量限速 | 肩/肘 60°/s | 直接沿用 `arm_manual.h` 的快速档角速度，防二连杆奇异区甩臂（踩坑 11） |
| 方向 | ↑ 上升 / ↓ 下降 / ← 向前伸出 / → 向后收回 | 只定义在 `arm_button.cpp` 的 `pad_axis_dz/dr()`，反了改符号 |

每拍从**当前命令角**重新正解，不积分目标：贴到行程/工作区边界自然停住，松手再按不跳变。
解支：`arm_ik_solve` 一次返回肘上/肘下两支，`arm_endpoint` 取离当前关节角更近的那支，避免摇杆把肘点过零点后方向键"四个键都变成同一个动作"。
与摇杆点动互斥（十字键优先），与动作互斥（按方向键先停动作）。

**动作选择菜单**（机械臂模式下按 R1 进入，再按 R1 退出）：菜单内 8 个键各对应一个动作槽位，
槽位表在 `arm_button.cpp` 的 `kMenuSlots[]`。**当前 8 个槽位全部占位**（2026/10/21：都是新动作，后续加），
新增时只改三处：`arm_action.h` 加 ActionId → `arm_action.cpp` 的 `kSequences[]` 登记路径 → `kMenuSlots[]` 换掉 `ActionId::kCount`。
菜单态屏蔽摇杆点动/夹爪/△×/十字键末端点动，但 **L2 与 SELECT 仍然有效**（安全相关）。

## 4. 烧录与验证流程

1. CLion 构建并烧录 `cmake-build-debug-stm32/CRTC2026_RobotA.elf`（全工程唯一产物）。
2. 先验 E3：工作位按 ×，底座摆向篮子侧并停住 → 新固件生效、底座方向正确。
3. 再验 E7：长按 D-pad ↑ 看末端是否**上升**（若方向不对，先查 `ARM_ENDPOINT_SHOULDER_OFFSET_DEG`，再查 `pad_axis_dz/dr` 的符号），
   同时确认贴到行程边界时是"停住"而不是"甩臂"。
4. 再验 E8：机械臂模式按 R1 进菜单（摇杆/夹爪应立即不响应），再按 R1 回正常。
5. 最后逐条过 E1~E6。
