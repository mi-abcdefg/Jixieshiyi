## 4. 用户角约定 ↔ 命令角 ↔ 占空比（核心换算数据）

用户角是 0~180 的"摇杆推杆方向"基准，与舵机安装方向解耦；关键帧一律以用户角存储。

### 4.1 换算宏（被删的 `arm_keyframe.h` 原文，main 分支 HEAD 版）

```c
#define ARM_UA_BASE_TO_CMD(u)    (90.0f + (u))    /* 底座：user 0=右推极限(工作侧,cmd90)，user 180=左推极限(篮子侧,cmd270) */
#define ARM_UA_LINK1_TO_CMD(u)   (180.0f - (u))   /* 肩：实测镜像——下推极限=user 180，上推极限=user 0 */
#define ARM_UA_LINK2_TO_CMD(u)   ((u) - 120.0f)   /* 肘：下推极限=user 0(cmd−120)，上推极限=user 180(+60) */
#define ARM_UA_BASE_FROM_CMD(c)  ((c) - 90.0f)    /* 篮内判定用读回 */
#define ARM_UA_LINK1_FROM_CMD(c) (180.0f - (c))
#define ARM_KF_KEEP              255.0f           /* 关键帧字段哨兵：保持当前值 */
```

**历史警告：底座宏换过一次方向。** 旧版是 `cmd = 270 − user`（user 0=左推/篮侧），2026/10/20 按 ×键 实测改成 `90 + user`。两版的关键帧数值相同，导致同一关键帧在新旧固件里物理落点相反——排查底座落点问题时先确认板上固件是哪一版（判别法见 §8）。

### 4.2 底座（SERVO_BASE_Z）完整对照表（当前宏，已验证到脉宽）

| 用户角 | 命令角 | 脉宽 | 物理位置 |
|---|---|---|---|
| 0 | 90° | **500µs（下限）** | 右推极限 = 工作侧 |
| 45 | 135° | 1000µs | — |
| 90 | 180° | 1500µs | 初始方位（臂朝车头） |
| 135 | 225° | 2000µs | — |
| 180 | 270° | 2500µs（上限） | 左推极限 = 篮子侧 |

肩/肘同理：肩 user 0→cmd 165→500µs（上推极限）、user 180→cmd 15→2500µs（下推极限）；肘 user 0→cmd −120→2500µs、user 180→cmd +60→500µs。脉宽 = 500 + ratio×2000，ratio=(cmd−min)/(max−min)，reversed 时 ratio 取反；**所有写入双重限幅，越界脉宽不可能出现**。

## 6. 动作路径与引擎参数（被删的 `arm_action.c` 设计）

### 6.1 路径定义

```c
/* 回收缩：篮内经篮上高点、篮外经外侧高点 */
retract_in[]  = { BASKET_HIGH, RETRACT };
retract_out[] = { OUTER_HIGH,  RETRACT };
/* 脱离伸展：升连杆 → 转底座 */
escape_path[] = { ESCAPE_LINKS, ESCAPE_BASE };
/* 篮内外转移：篮外→篮内 经外侧→篮上 到篮内点；篮内→篮外 反向到拾取低点 */
transit_in[]  = { BASKET_HIGH, OUTER_HIGH, PICKUP_LOW };  /* 起点判为篮内时走这条 */
transit_out[] = { OUTER_HIGH,  BASKET_HIGH, BASKET_IN };
/* 占位：place/grab = { HOME, HOME_OPEN/CLOSE, HOME } */
```

### 6.2 篮内判定（启动那一刻判定一次，之后不切换）

```c
#define ARM_IN_BASKET_BASE_USER_MIN     160.0f
#define ARM_IN_BASKET_SHOULDER_USER_MAX 100.0f
/* 底座用户角 ≥160 且 肩用户角 ≤100 → 判为篮内 */
```

**大坑**：该阈值是"用户角"域的，其物理含义随换算宏翻转——旧宏（270−u）下这个域对应命令角 ≤110°，**把正常工作位判成篮内**，×键 全程走反路径。换宏必须同步复核这两个阈值（须复核项，见 §8）。

### 6.3 引擎参数与推进方式

- `ARM_ACTION_HOLD_MS = 300`：每帧到位后停留。
- `ARM_ACTION_TICK_S = 0.020f`：步进周期，必须与 ArmTask 的 20ms 一致。
- 推进：`begin_keyframe` 把用户角换算成命令角（KEEP 字段取当前命令角），三关节以各自快速档角速度步进逼近（底座 90°/s、肩 60°、肘 60，即点动宏）；全部到位后按帧切夹爪，停留后进下一帧；完成后回 IDLE。
- 取消语义：运行中再次触发/SELECT/推杆 → `cancel()` 保持当前位置。**实测教训：打断阈值要 0.15，不能沿用 0.02 点动死区**（文档 §9.13，防摇杆静置漂移在第一帧误杀动作；d05e884 曾修过被整笔 revert，数据没丢）。
- 已知坑：动作完成后不要停在 FINISHED 状态（会闹出"首次 L2 要按两次"），完成直接回 IDLE。
