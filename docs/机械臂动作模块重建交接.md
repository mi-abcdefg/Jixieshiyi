# 机械臂动作模块·重建规格

> `feature/arm-jog-only` 分支的机械臂当前是**纯摇杆点动基线**。本文件是动作模块的重建规格：
> 要达成什么效果、怎么构建、以及必需的数据。按本文件实现即可，无需翻阅旧代码；
> 如需参考，旧实现完整保留在 main 分支（例：`git show main:Arm/Src/arm_action.c`）。
> 最后更新：2026/10/20

---

## 1. 目标效果（实现完成的验收标准）

| 编号 | 效果 | 验收方法 |
|---|---|---|
| E1 | ○ 键：夹爪在"开 / 合"两档间切换，两档角度实车标定 | 任一位置按 ○，两档往返稳定 |
| E2 | 十字键↑：回收缩——从任意位形经过渡点收到收缩位 (0,165,0)，夹爪闭合 | 任意姿态按 ↑，臂按路径收拢不扫到周围 |
| E3 | × 键：篮内外转移——篮外→篮内经两个过渡点到篮内点；篮内→篮外反向到拾取低点；走向按起始位形自动判定 | 从工作位按 ×，**底座必须摆向篮子侧并停在篮内点**（此条同时是"新固件已生效"的判据） |
| E4 | L2 键：卸力（可徒手摆位）⇄ 恢复；恢复后自动执行"脱离"动作（先抬两段连杆、再回转底座）远离卡住区 | 卸力恢复后臂自动走出当前位置 |
| E5 | 通用：动作运行中推杆 / SELECT / 再次动作键可打断，臂停在当前位置 | 动作中推杆立即停 |
| E6 | 运动品质：各关节恒角速度、到位停留约 0.3s、指定帧切换夹爪、动作完成后回到空闲可立即触发下一个 | 连续触发不卡死 |

## 2. 构建思路

### 2.1 模块划分（全部 C++，推荐命名）

| 模块 | 文件 | 职责 | 关键接口 |
|---|---|---|---|
| 关键帧层 | `Arm/Inc/arm_keyframe.h` `Arm/Src/arm_keyframe.cpp` | 纯数据：用户角→命令角换算 + 命名关键帧表。**改角度只改这里** | `ArmKeyframe get_keyframe(KeyframeId id)` |
| 动作引擎 | `Arm/Inc/arm_action.h` `Arm/Src/arm_action.cpp` | 状态机：按路径表逐帧逼近关键帧、切夹爪、推进/取消。**不认识按键和 PS2** | `start(ActionId, now_ms)` `update(now_ms)` `cancel()` `get_state()` |
| 按键输入 | `Arm/Inc/arm_button.h` `Arm/Src/arm_button.cpp` | PS2 位图 → 边沿事件 → 按键决策（E1~E5 的绑定都在这里） | `feed(buttons, connected)` `take_events()` `apply(now_ms)` |

编排（已有，不需新建）：`arm_task.cpp` 每周期喂按键 → 调 `apply()` → 调 `arm_action_update()`；摇杆点动照旧走 `arm_manual`。

命名沿用工程现有 snake_case；新文件全部 `.cpp`，接口直接用 C++（全链路无 C 编译单元，**不需要 extern "C"**）。旧版的 gamepad/robot_control 两层合并为 `arm_button` 一个模块。

### 2.2 引擎设计要点

1. **数据与逻辑分离**：引擎只认 `KeyframeId` 序列；角度全部来自关键帧表。
2. **路径**：每个动作 = 一个 `KeyframeId` 数组。转移类动作准备两条等长路径，启动那一刻按当前位形二选一，之后不再切换。
3. **推进**：以 20ms 固定节拍步进（与 `ArmTask` 周期严格一致）。每帧先把用户角换算为命令角目标（哨兵 KEEP = 保持该关节当前值），三关节以恒角速度逼近（底座 90°/s、肩 60°/s、肘 60°/s，与点动快速档同源 `arm_manual.h`）；全部到位后按该帧定义切换夹爪，停留 ~300ms 进下一帧。
4. **状态机**：`IDLE → RUNNING → IDLE`。取消 = 保持当前位置立即回 IDLE；**正常完成也直接回 IDLE**（不留中间态）。
5. **打断**：运行中任一摇杆轴越过**打断阈值**即取消。打断阈值必须显著大于点动死区（建议 0.15 vs 0.02），否则摇杆静置漂移会在第一帧误杀动作。
6. **关节写入**：一律经 `arm_control` 的 `arm_get_pose()/arm_set_pose()`（读回=命令角，非反馈）；夹爪经 `gripper_jog`（本分支仅剩点动，两档切换在重建时加回）。

### 2.3 工程要求

- 新源文件登记进 `CMakeLists.txt` 的 `add_executable`；`Arm/Inc` 已在 include 路径，无需改。
- 构建命令：`ninja.exe -C cmake-build-debug-stm32`（全工程唯一烧录产物 `CRTC2026_RobotA.elf` 在该目录）。
- 分层铁律：`Arm/` 不 include PS2 与 Task；PS2 读取接口只有 RemoteCommTask 能调；`ControlMode` 只有底盘任务写。
- 链接带 `--gc-sections`：不可达代码会被整段裁掉；确认新模块已链接查 `.map`，不在 `Discarded input sections` 里即生效。

## 3. 必需数据（实现时照抄，实车标定后更新数值）

### 3.1 舵机通道与角度域（`servo_driver.cpp` 配置表，勿改）

| 关节 | 通道/引脚 | 舵机 | 命令角域 | 上电初始 | reversed |
|---|---|---|---|---|---|
| 夹爪 SERVO_GRIPPER | TIM4_CH1 / PB6 | SG90 | [0°, 180°] | 90° | false |
| 肩 SERVO_LINK_1 | TIM4_CH2 / PB7 | SG90（11cm 连杆） | [15°, 165°] | 90° | true |
| 肘 SERVO_LINK_2 | TIM4_CH3 / PB8 | SG90（8.5cm 连杆） | [−120°, +60°] | −30° | true |
| 底座 SERVO_BASE_Z | TIM4_CH4 / PB9 | MG995（绕 Z） | [90°, 270°] | 180° | false |

脉宽恒为 500~2500µs；脉宽 = 500 + ratio×2000，ratio = (命令角−min)/(max−min)，reversed 时取反。所有写入双重限幅，越界脉宽不会出现。底座命令角 180° = 臂朝车头方向。

### 3.2 用户角换算（关键帧存储用 0~180 用户角，与安装方向解耦）

```cpp
constexpr float kKeep = 255.0f;              // 关键帧字段哨兵：保持当前值
constexpr float base_user_to_cmd(float u)     { return 90.0f + u; }   // user 0=工作侧端(cmd 90)，180=篮子侧端(cmd 270)
constexpr float link1_user_to_cmd(float u)    { return 180.0f - u; }  // 肩：user 0=上推极限，180=下推极限
constexpr float link2_user_to_cmd(float u)    { return u - 120.0f; }  // 肘：user 0=下推极限(cmd −120)，180=上推极限(+60)
constexpr float base_cmd_to_user(float c)     { return c - 90.0f; }   // 位形判定用读回
constexpr float link1_cmd_to_user(float c)    { return 180.0f - c; }
```

**标定项**：底座 user 0/180 与物理两端的对应关系（上表为当前约定）须在整车复核一次——×键验收（E3）同时完成此项：底座该摆向篮子侧而实际摆反，则翻转 `base_user_to_cmd / base_cmd_to_user` 两行，并同步复核 3.4 的篮内判定阈值。

### 3.3 底座换算自检样例

| 用户角 | 命令角 | 脉宽 | 物理位置 |
|---|---|---|---|
| 0 | 90° | 500µs（下限） | 工作侧端 |
| 90 | 180° | 1500µs | 初始方位（臂朝车头） |
| 180 | 270° | 2500µs（上限） | 篮子侧端 |

### 3.4 关键帧初始值（底座, 肩, 肘 = 用户角；夹爪 = 开/合/不变）

| KeyframeId | 底座 | 肩 | 肘 | 夹爪 | 用途 |
|---|---|---|---|---|---|
| `kBasketHigh` 篮上高点 | 180 | 90 | 90 | — | 篮子上方过渡位 |
| `kOuterHigh` 外侧高点 | 90 | 100 | 80 | — | 初始位附近过渡位 |
| `kRetract` 收缩位 | 0 | 165 | 0 | 合 | 回收缩终点 |
| `kBasketIn` 篮内点 | 175 | 70 | 25 | 开 | 转移·篮侧端点 |
| `kPickupLow` 拾取低点 | 90 | 75 | 40 | 开 | 转移·外侧端点 |
| `kEscapeLift` 脱离1 | KEEP | 90 | 90 | — | 抬两段连杆，底座不动 |
| `kEscapeYaw` 脱离2 | 90 | KEEP | KEEP | — | 底座回中位 |

篮内判定（转移动作选路用）：`底座用户角 ≥ 160 且 肩用户角 ≤ 100` → 判为篮内。阈值随底座宏方向联动复核（见 3.2 标定项）。

### 3.5 动作路径与按键绑定

```cpp
retract   : 篮内 { kBasketHigh, kRetract } / 篮外 { kOuterHigh, kRetract }      // 十字键↑
transit   : 篮内 { kBasketHigh, kOuterHigh, kPickupLow }
            篮外 { kOuterHigh, kBasketHigh, kBasketIn }                          // ×
escape    : { kEscapeLift, kEscapeYaw }                                          // L2 恢复后自动
```

○ = 夹爪两档切换（档位角起 60/120 命令角，实车标定后更新）；L1 = 点动快/慢两档（`arm_manual` 机制已在，绑回即可）。动作运行中：推杆/SELECT/动作键打断（E5）。
